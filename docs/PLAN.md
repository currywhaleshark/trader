# 아키텍처와 M0~M5 개발 계획

기준 문서: [SPEC_v0.1.md](SPEC_v0.1.md) (현대 국제무역 시뮬레이터 — 에이전트 개발 요구서 v0.1)

## 1. 기술 선택과 이유

| 선택 | 이유 |
| --- | --- |
| Vite + TypeScript | 서버 없이 도는 브라우저 웹앱(§13). 시뮬레이션 코드를 Node(테스트·오프라인 생성)와 브라우저가 그대로 공유한다. |
| Three.js | 구형 행성 렌더링(§13 권장). 지구본은 등장방형 텍스처 한 장을 구에 입히는 방식이라 저사양에서도 가볍다. |
| React | M2 이후 회사·무역·도시 패널이 많아진다. 3D/2D 캔버스는 React 밖의 일반 클래스로 두고, 패널만 React로 그린다. |
| Vitest | 시뮬레이션 단위 테스트(§13). DOM 없이 `src/sim`만 돌린다. |
| tsx | 오프라인 세계 생성 스크립트 실행(`npm run gen:world`). |

## 2. 계층 구조

```
src/sim/      순수 TypeScript. DOM·Three.js·React를 import 하지 않는다.
  core/       SeededRNG, 3D 노이즈, 구면 기하, 격자, 그리드 탐색(Dijkstra/A*)
  world/      세계 생성 파이프라인, World 타입, 직렬화, 런타임 항로 탐색
  (M1~)       economy/, trade/, policy/ … 월별 틱: State + Commands + RNG -> NextState + Events
src/render/   World(데이터) -> 그림. baseLayer(순수, PNG 미리보기와 공유) / compose / GlobeView / MapView
src/ui/       React 패널. sim을 읽기만 하고, 명령(Command)으로만 상태를 바꾼다(M2~).
scripts/      gen-world(오프라인 생성), preview(PNG 미리보기)
tests/        sim 단위·통합 테스트
```

핵심 규칙

- **데이터와 렌더링의 분리:** `World`는 형식화 배열(레이어)과 JSON(국가·도시·항로)뿐이다. 3D 지구본과 2D 지도는 같은 `World`에서 같은 등장방형 그림을 만들어 쓴다.
- **시드 재현성:** 모든 난수는 `SeededRNG.fork(label)`에서 나온다. 단계별로 독립 스트림이라 한 단계를 고쳐도 다른 단계의 난수열이 밀리지 않는다. 같은 시드 → 같은 `world.hash`.
- **오프라인 기후:** 기후·지형은 `gen-world`가 한 번 계산해 `public/world/world.json + world.bin`으로 저장한다. 런타임은 읽기만 한다(§3.3). 런타임에 다시 도는 것은 해협 봉쇄 시의 항로 탐색(A*)뿐이다.
- **설정 데이터:** 대륙 청사진, 해협, 국가·도시 앵커, 기후 계수, 작물·자원 규칙은 모두 [src/sim/world/config.ts](../src/sim/world/config.ts)에 있다.

## 3. 세계 생성 파이프라인 (M0)

좌표계는 위경도 하나. 격자는 등장방형 720×360(0.5°), 행성 반지름 6371km.

1. **대륙** — 설정의 "캡슐"(구면 위 선분+반지름) 청사진을 시드로 조금 흔들고 3D 노이즈로 해안선을 만든다. 대륙별 위도 한계와 해협 수로를 강제한다.
2. **고도** — 해안 거리, 청사진 산맥(시드로 흔듦), 노이즈.
3. **바다 구역** — 외해 / 중앙해 / 관문 해협(봉쇄 가능 구역) / 항해 불가(극지).
4. **기후** — 월별 기온(위도·고도·대륙도·해류), 월별 강수(계절에 따라 이동하는 탁월풍대의 수증기 이류, 지형성 강수·비그늘, 적도 수렴대). 12개월×셀로 저장.
5. **하천** — priority-flood 유향 + 강수 누적.
6. **기후대** — 쾨펜 단순화 10종.
7. **농업** — 작물별 적합도, 수확 월 분포(남북반구가 자동으로 반대가 된다).
8. **자원** — 기후와 무관한 지질 규칙(철광석: 구릉·산록, 원유: 저지 분지·대륙붕).
9. **국가** — 앵커에서 고도 가중 Dijkstra로 영토 분할(국경이 산맥을 따른다).
10. **도시·항구** — 앵커 주변 해안에서 하구·만·저지 점수로 선정.
11. **배후지** — 도시별 월 기온·강수, 작물 월별 생산 계수, 자원량 집계(M1 경제의 입력).
12. **해상 항로** — 바다 셀 그래프 Dijkstra → 대권 직선화 → 항구 쌍별 경로·거리·통과 해협.
13. **검증** — 대륙 배치, 6개국, 항구 연결, 육지 관통 없음, 기후·작물·자원 다양성.

## 4. 단계별 계획

| 단계 | 내용 | 주요 모듈 | 완료 판정 |
| --- | --- | --- | --- |
| **M0** | 구형 세계·기후·항로, 3D/2D 뷰어 | `sim/world`, `render` | §14 M0 완료 조건 + 검증 리포트 통과 |

| **M2** | 플레이어 회사: 수동 거래, 항해, 선박 구매, 자동항로, 장부 | `sim/company`, `sim/ship`, `ui/trade` | 이익→다음 배 구매 가능, 선박별 경제성 차이, 자동항로 불변 조건 |
| **M3** | 산업 투자·쇠퇴, 인구·소득, 항만 성장, NPC 경쟁 | `sim/growth` (연 단위 틱) | 30년 실행에서 수출입 구조 변화, 발산 없음 |
| **M4** | 관세·협정·갈등, 원산지, 문화 이벤트, 브랜드 | `sim/policy`, `sim/events` | 관세가 도착원가를 바꿈, 환적 원산지 유지 |

각 단계는 앞 단계가 테스트와 화면에서 확인된 뒤 시작한다.

## 5. M0가 M1에 넘겨주는 것

- `world.cities[].region` — 도시 배후지의 월 기온·강수, 작물별 적합도·경작 가능 면적·**월별 생산 계수**, 자원 매장량.
- `world.seaRoutes` — 항구 쌍별 거리(km)·경유점·통과 해협. 봉쇄 시 `findSeaRoute()`로 재탐색.
- `world.layers.seaRisk` — 기본 해상 위험 계수.
- `SeededRNG` 상태 직렬화 — 저장/이어하기와 재현 실행의 기반.

## 6. M1 구현 메모

- **월별 틱** `stepMonth(ctx, state, commands) -> { state, events }` ([step.ts](../src/sim/economy/step.ts)). 입력 상태를 바꾸지 않고, 난수는 상태 안의 시드에서만 나온다. 순서: 생산(투입재 차감) → 소비 → 선박 도착·거래 → 가격 갱신.
- **초기화** ([setup.ts](../src/sim/economy/setup.ts)): 세계 총수요에서 거꾸로 필요 생산량을 구하고, 공장은 시나리오 데이터가 정한 도시에(기술 수준 미달이면 없음), 농장·광산은 M0의 배후지 통계가 정한 도시에만 세운다.
- **가격** ([market.ts](../src/sim/economy/market.ts)): 재고/목표 재고 비율로만 움직이고 한 달에 일부만 조정된다. 난수로 가격을 흔들지 않는다. 매매에는 호가 차이와 거래량에 따른 가격 충격이 있어 같은 항구 왕복 매매는 반드시 손해다.
- **원료값 전달**: 공장은 시세가 생산비(투입재 시세 + 운영비)에 못 미치면 가동을 줄인다. 원료가 비싸지면 공급이 줄고, 그 결과 제품값이 오른다.
- **NPC** ([npc.ts](../src/sim/economy/npc.ts)): 도착하면 화물을 팔고, 세계의 모든 (사는 곳, 파는 곳) 쌍에서 시간 대비 이익이 큰 거래를 고른다. 필요하면 빈 배로 이동한다. 플레이어와 같은 시장 함수를 쓴다.
- **M2로 넘기는 것**: `quoteBuy/quoteSell/executeBuy/executeSell`, `CargoLot`(원산지 보존), `Ship`의 출발·도착 시각, `Command` 큐.

## 7. M1 밸런스 조정 기록

측정 도구: `npm run sim -- --years 10 [--seed …]` ([metrics.ts](../src/sim/economy/metrics.ts)). 첫 1년은 적응 기간으로 빼고, 사람들이 실제로 치른 값(소비·투입량 가중), 부족률, 가동률, 상한 근접 비율을 본다.

| 지표 (기본 시드, 2~10년차) | 조정 전 | 조정 후 |
| --- | --- | --- |
| 최대 부족률 | 23% (철강) | 0.6% |
| 지불가격(기준 대비) | 1.1~1.5배, 작은 시장은 상한 4배 | 1.04~1.38배, 상한 근접 0% |
| 공장 가동률 | 65~75% | 71~90% |
| NPC 회사 현금(10년) | 시작의 약 8배, 계속 증가 | 1.6~1.9배에서 멈춤 |

고친 원인

1. **생산비**: 운영비를 기준가의 고정 비율로 잡아 전자부품 생산비가 기준가의 3분의 1이었다. 값이 반값이 돼도 공장이 최대로 돌아 생산지에 재고가 쌓였다. → 모든 값이 기준가일 때 생산비가 기준가의 82%가 되도록 운영비를 역산한다(`costShare`).
2. **작은 시장 방치**: 수요가 월 0.1개인 시장은 "1개 미만"이라 배가 싣지 않았다. → 최소 적재 단위를 0.2로(`minLotQuantity`), 적재 공간이 남으면 작은 상품을 덤으로 싣는다.
3. **생산지의 수출 대기 재고**: 생산지가 배를 기다리는 재고를 과잉으로 보고 값을 낮춰 스스로 감산했다. → 생산지 목표 재고에 남는 생산의 몇 달치를 더한다(`exportBufferMonths`, 작물은 `cropStorageMonths`).
4. **수입품 되팔기**: NPC가 수입 도시의 재고까지 사 가 다른 곳에 되팔았다. → 도시는 자기 쓸 몫(`reserveShare`)은 팔지 않는다. 플레이어에게도 같은 규칙이 적용된다.
5. **입항과 소비의 순서, 비축 기간**: 재고가 바닥난 뒤에야 값이 올라 배가 출발했고, 배가 도착한 달에도 소비가 먼저 처리돼 한 달 더 굶었다. → 월 순서를 생산 → 입항·거래 → 소비로 바꾸고, 직접 만들지 않는 상품은 2달치를 더 비축한다(`importBufferMonths`).
6. **돈이 쌓이기만 함**: 무역 이익이 회사에 쌓이기만 했다. → 운영 자금(`workingCapital`)을 넘는 현금의 25%를 매달 본거지 도시에 배당·세금으로 낸다.

남은 한계

- 도시 수지(`treasury`)는 아직 장부일 뿐이다. 수입 도시는 적자가, NPC 본거지는 흑자가 계속 쌓인다. 소득·임금·저축으로 돈이 다시 도는 구조는 M3(인구·소득 변화)에서 만든다.
- 철광석·철강의 지불가격이 1.3~1.4배로 높은 편이다. 값싼 벌크 화물이라 운임이 값의 3분의 1을 차지하기 때문이며, 현실에서도 원료 수입국이 더 비싸게 산다는 교육적 사례로 둔다.

회귀 방지: `tests/economy.test.ts`의 "균형" 묶음이 부족률 3% 미만, 지불가격 0.85~1.5배, 상한 근접 2% 미만, 가동률 60~95%, 회사 현금 시작의 0.5~2.5배를 검사한다.

## 8. M2 구현 메모 — 플레이 가능한 무역회사

모듈: [player.ts](../src/sim/economy/player.ts)(명령·항해·장부·자동항로), [advice.ts](../src/sim/economy/advice.ts)(거래 힌트), [start.ts](../src/sim/economy/start.ts)(게임 시작), [bot.ts](../src/sim/economy/bot.ts)(밸런싱용 자동 플레이어).

- **명령**: `applyCommand(ctx, state, cmd) → { ok, error, events }`. 거래(`trade`)·출항(`sail`)·선박 매매(`buyShip`/`sellShip`)·항로(`saveRoute`/`deleteRoute`/`assignRoute`). 실패하면 학생이 읽을 이유를 돌려주고 상태를 바꾸지 않는다. 화면은 복제본에 적용하고, `stepMonth`도 같은 함수로 명령 큐를 처리한다.
- **시장 규칙은 NPC와 같다**: 같은 `quoteBuy/quoteSell`, 도시 비축분(`reserve`) 아래로는 살 수 없음, 거래량에 따른 가격 충격.
- **비용**: 연료비(1000km당, 짐 양과 무관 → 큰 배는 가득 실어야 이득), 항만비(부피당, 싣고 내릴 때), 매달 유지비. 현금은 음수가 되지 않고, 못 낸 유지비는 `arrears`로 남아 다음 수입에서 먼저 갚는다.
- **선종 5종**([data.ts](../src/sim/economy/data.ts) `shipTypes`): 크기 등급이 항구 규모보다 크면 못 들어간다. 벌크선은 벌크만, 컨테이너선은 공산품만 싣는다. 과일은 냉장선이 아니면 항해 중 달마다 12%가 상한다(상한 양은 `state.spoiled`로 보존 검증에 포함).
- **자동항로**: 기항지마다 팔 상품·살 상품(최대량). 다음에 그 상품을 파는 기항지의 예상 값으로 이익률을 계산해 `minMargin` 미만이면 사지 않고 알림, `cashReserve` 아래로는 쓰지 않는다(항만비 포함). 연료비가 모자라면 한 달 기다린다.
- **예상 도착가**(`forecastPrice`): 지금 재고 + 이미 실어 오는 배들의 짐 + 내 짐 − 항해 중 소비량으로 정착할 값. 힌트와 거래 표의 "1개당 남는 돈"이 이 값을 쓴다.
- **게임 시작**: 경제를 1년(`warmupMonths`) 먼저 돌린 뒤 회사를 세운다. 0개월째에는 모든 도시가 기준가라 남는 거래가 없기 때문이다.

### M2 밸런싱 기록

`npm run play -- --years 10 --ships small,medium [--keep 25000]`(봇 플레이어)로 쟀다.

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| 작은 배 한 척이 8년 내내 적자 | NPC 30척이 값 차이를 거의 다 메움, 연료비가 이익을 먹음 | NPC 회사당 10척 → 6척, 선종별 연료·유지비 하향 |
